# جرد وظيفة الضبط (ضبط الجودة) في قسم التصنيع — 2026-10-02

**النطاق:** قسم التصنيع بالكامل (قاعدة البيانات + RBAC + الخدمات + الواجهة)، مقروءًا
من زاوية وظيفة «قسم الضبط»: الفحص، وقرار القبول أو الرفض، وحسم التالف وإعادة التشغيل،
وسلطة الإفراج عن الإنتاج التام، والفصل بين من ينتج ومن يحكم على الجودة.

**مصدر الأدلة:**

- المستودع: `main@3acea30` (Baseline `000_schema_baseline_20260905_184634.sql`، cutoff 189،
  ثم Migrations 190–198).
- Production `uutfztmqvajmsxnrqeiv`: قراءة حية بتاريخ 2026-10-02 داخل
  `BEGIN READ ONLY … ROLLBACK`، عبارة عن أعداد مجمّعة وفحوص كتالوج فقط، دون أي صف
  تجاري أو معرّف مؤسسة (§5).

**طبيعة الوثيقة:** هذا جرد لا تنفيذ. لا تغيّر الوثيقة أي Migration أو كود، ولا تجيز
تطبيق شيء على Production.

## 1) الخلاصة التنفيذية

وظيفة الضبط **ليست مفقودة بالكامل، بل موجودة كهيكل خامل غير موصول.** هناك جدول فحوص،
وحالة `quality_check` في دورة أمر التصنيع، وعلم `requires_inspection` على عمليات
المسار، ودوال خدمة وhooks للفحص، وصفحة `/quality` في القائمة. لكن:

1. **لا توجد بوابة:** لا يمر أي مسار تشغيلي (إتمام عملية، إتمام أمر عمل، إتمام أمر
   تصنيع، دخول المخزون التام) عبر فحص أو قرار جودة.
2. **لا توجد سلطة:** لا يوجد مفتاح صلاحية واحد للجودة في كتالوج RBAC، ولا قالب دور،
   ولا دور حي. ويكفي أي عضو في المؤسسة لنقل الأمر إلى `quality_check` أو إخراجه منها.
3. **لا يوجد فصل للمهام:** العامل نفسه يُدخل كمية الإنتاج وكمية التالف، ويُدخلها
   محاسب التكاليف نفسه في شاشة تكلفة المرحلة؛ ولا يتحقق منها طرف مستقل.
4. **لا توجد واجهة:** صفحة `/quality` حالة فارغة ثابتة («قريبًا»)، وhooks الفحص
   مكتوبة لكن لا يستدعيها أي مكوّن.
5. **الحالة الحية:** صفر فحوص مسجلة، وصفر عمليات مسار تتطلب فحصًا، وأمر تصنيع واحد
   من ثلاثة **عالق حاليًا في `quality_check`** بلا أي سجل فحص يبرّر دخوله أو يحكم
   خروجه.

النتيجة العملية: الإنتاج التام يدخل المخزون ويُقيَّم ويُرحَّل محاسبيًا **دون إفراج جودة**،
والتالف «يُعلَن» ذاتيًا ولا «يُثبَت»، والتالف غير العادي لا يصل إلى دفتر الأستاذ.

## 6) مسار مقترح (للقرار لا للتنفيذ)

### 6.1 قرارات يجب أن يحسمها المالك قبل أي كود

1. **وحدة الفحص:** أمر التصنيع، أم المرحلة (`stage_wip_log`)، أم أمر العمل؟ النظام
   مرحلي التكاليف، وأوامر العمل صفر حيًا، فالأرجح «المرحلة + فحص نهائي على الأمر»
   بدل الارتباط الإلزامي بأمر العمل.
2. **إلزامية البوابة:** إلزامية لكل منتج، أم حسب المنتج أو المسار عبر `requires_inspection`؟
3. **قرارات الحسم:** قبول، رفض إلى خردة، إعادة تشغيل، قبول مشروط (بمن يعتمد؟).
4. **محاسبة التالف:** التحقق من حسابات `NORMAL_SCRAP` و`ABNORMAL_SCRAP` (خاصة دائن
   `ABNORMAL_SCRAP`)، وتوقيت الترحيل (عند الحسم أم عند الإتمام).
5. **الفصل بين المهام:** هل يُمنع من سجّل الإنتاج من اعتماد فحصه؟ وهل يخضع مسؤول
   المؤسسة لهذا المنع، أي هل تُصنّف مفاتيح الإفراج «حساسة» عبر
   `wardah_is_sensitive_permission` كما في 174؟

### 6.2 تسلسل PRs مقترح (يتبع قاعدة repository-first ثم DB-first)

| # | النوع | المحتوى |
|---|---|---|
| 1 | DB | مفاتيح RBAC جديدة (مثل `manufacturing.quality.read/inspect/release/disposition`) + قالب دور «مراقب جودة»؛ إضافة فقط |
| 2 | DB | RPC ذرية لتسجيل الفحص (تضبط `inspector_id = auth.uid()`، رقم تسلسلي فريد، حارس صلاحية) + إغلاق `INSERT/UPDATE` المباشر وسحب `anon` + trigger ثبات بعد التسجيل + تدقيق |
| 3 | DB | إغلاق `rpc_transition_mo_status` بصلاحيات حسب الانتقال (يتقاطع مع X2)، واشتراط فحص `FINAL` ناجح للخروج من `quality_check` إلى `done` |
| 4 | DB | بوابة الإفراج داخل منسّق الإتمام الطرفي (#230): لا مخزون تام دون إفراج، والكمية المقبولة فقط تدخل المخزون التام |
| 5 | DB | حسم التالف: كيان Disposition + ترحيل `ABNORMAL_SCRAP` بعد تصحيح التعيين + تمثيل التالف في `stage_wip_log` (عمود nullable إضافي، لا تعديل للقيد القائم دون قرار) |
| 6 | UI | صفحة `/quality` حقيقية (طابور الفحص، تسجيل، إفراج، حسم) + مواءمة آلة الحالات + إزالة `quality_check` من الاختيار اليدوي — بعد تطبيق 1–4 على Production والتحقق منها |
| 7 | DB+UI | الفحص الوارد: مسار حسم `pending_inspection` ومخزن حجر (يتبع 148) |

كل خطوة DB تحتاج runbook وقبول Fresh DB واختبارات سلبية (مستخدم بلا صلاحية، مؤسسة
أخرى، إعادة الإرسال، تعديل بعد الاعتماد).

## 7) ما لا يثبته هذا الجرد

- لم تُشغَّل أي واجهة أو جلسة مستخدم أو اختبار كتابة على Production أو Staging.
- لم يُفحص Staging (ثقته مصنفة **UNVERIFIED / REBUILD RECOMMENDED**).
- سبب دخول الأمر الحي الوحيد إلى `quality_check` ومن نقله غير معروف؛ لم تُقرأ صفوف تجارية.
- لا يحدد الجرد تصميمًا نهائيًا؛ §6 اقتراح يحتاج قرارات المالك أولًا.
