# Trial Balance Contract — Migrations 182 → 183

**العقد الحي:** جسم الدفتر القانوني من 182 + صلاحية القراءة المالية التامة من 183  
**الدالة:** `public.rpc_get_trial_balance(uuid, date)`  
**المبدأ:** لا توجد Migration «أخيرة تفوز»؛ أي استبدال لاحق يعيد تثبيت الطبقتين معًا.

## لماذا هذه السلسلة مركبة

Migration 182 صححت صحة التقرير: نقلت القراءة إلى
`gl_entries/gl_entry_lines`، اشتقت افتتاحي السنة المالية، حافظت على الحسابات
المعطلة ذات الحركة، استردت الأسطر التاريخية ذات `account_id IS NULL` عبر الرمز،
وصححت الاسم العربي.

Migration 183 تصحح حدود الوصول: عضوية المؤسسة وحدها لم تعد كافية لاستدعاء
الـRPC مباشرة. بعد حارس العضوية تطلب الدالة
`reports.financial.read` عبر `wardah_178_assert_permission`، وهو يغلف
`wardah_has_exact_permission` ويحافظ على عقد RBAC المركزي.

لو أُعيد جسم 182 بلا طبقة 183 عاد التسريب الأمني. ولو أُعيدت طبقة 183 فوق جسم
قديم عاد التقرير إلى دفتر تاريخي خاطئ. لذلك العقد الصحيح هو اتحادهما.

## الطبقة 182 — صحة البيانات

الخصائص الآتية لازمة ولا يجوز إسقاط واحدة منها:

| الخاصية         | العقد                                                        |
| --------------- | ------------------------------------------------------------ |
| المصدر          | `gl_entries` + `gl_entry_lines` فقط                          |
| حالة القيد      | `posted`                                                     |
| التاريخ         | حتى `p_as_of_date`                                           |
| الافتتاحي       | قبل بداية السنة المالية التي تحتوي تاريخ التقرير             |
| مصدر السنة      | `accounting_periods`، وإلا `organizations.fiscal_year_start` |
| الاكتمال        | لا تصفية بـ`allow_posting/is_active`                         |
| المرجع التاريخي | `account_id IS NULL` يُحل بـ`account_code` داخل المؤسسة      |
| الاسم العربي    | `COALESCE(a.name_ar, a.name, l.account_name)`                |
| التوقيع         | overload واحد: `(uuid,date)`                                 |
| الإرجاع         | الأعمدة العشرة نفسها بلا تغيير                               |
| العزل           | `wardah_assert_org_member` قبل القراءة                       |

## الطبقة 183 — صلاحية القراءة

بعد تحديد المؤسسة وإثبات عضويتها:

```sql
PERFORM public.wardah_178_assert_permission(
  v_org, 'reports.financial.read');
```

المفتاح موجود في لقطة البيانات المرجعية الحية؛ لم تُضف 183 اسمًا جديدًا ولم
تزرع منحة تلقائية. دلالة `wardah_has_exact_permission` تبقى كما هي:

- Super Admin يتجاوز.
- Org Admin النشط يتجاوز للمفاتيح غير الحساسة.
- غير المدير يحتاج دورًا نشطًا داخل المؤسسة، ومنحة المفتاح نفسه، وتعيينًا غير
  منتهي.
- تعطيل الدور أو انتهاء التعيين أو حذف `role_permissions` يُبطل الوصول فورًا.

في `auth.uid()` وفق عقد المساعد المركزي.

## شبكة القبول

`financial-report-rbac-183-acceptance.yml` تبني قاعدتين من الزوج الحالي
للـBaseline:

1. **قبل 183:** تستبعد الملف وتثبت فعليًا أن عضوًا نشطًا بلا أي دور يستطيع
   استدعاء الحدود الأربعة. نجاح هذا السيناريو هو إثبات الاحمرار.
2. **بعد 183:** تطبق السلسلة كاملة وتثبت المنع/السماح الحقيقيين.

الحالات الخضراء تشمل:

- عضو بلا صلاحية: مرفوض.
- `reports.inventory.read` لا يحقق `reports.financial.read`: مرفوض.
- المنح التام: مسموح.
- كشف الحساب وحسابات GL لا تتبادلان المفاتيح.
- دور منتهي أو معطل: مرفوض.
- منح يعمل ثم يُسحب: مرفوض فور السحب.
- مؤسسة أخرى: `NOT_ORG_MEMBER`.
- Org Admin النشط: يبقى مطابقًا لعقد RBAC المركزي.
- `anon`: لا EXECUTE.

وبالتوازي، بوابة Ledger Truth تُطلق على أي تغيير في
`sql/migrations/**`. حالات LT-2 وA–E تحرس جسم 182، بما فيها سنة يوليو،
الحساب المعطل، `account_id IS NULL` والاسم العربي.

## قاعدة أي استبدال لاحق

قبل قبول أي `CREATE OR REPLACE FUNCTION rpc_get_trial_balance` لاحق يجب أن
يثبت الكاتب جميع الآتي في التعريف النهائي:

1. حارس العضوية موجود ويعمل قبل القراءة.
2. `reports.financial.read` يُفحص عبر المساعد المركزي التام.
3. جسم الدفتر القانوني لا يقرأ `journal_entries/journal_lines`.
4. مسار `accounting_periods` واحتياطي `fiscal_year_start` باقيان.
5. الحسابات ذات الحركة لا تُحذف بسبب حالة الحساب.
6. حل `account_id IS NULL` والاسم العربي باقيان.
7. التوقيع وشكل الإرجاع وعدد الـoverloads والمنح لم تتغير.
8. بوابتا Financial RBAC وLedger Truth خضراوان مع إثبات الاحمرار.

لا يجوز نسخ 182 وحدها أو إضافة حارس 183 إلى نسخة أقدم من جسم الدالة.
