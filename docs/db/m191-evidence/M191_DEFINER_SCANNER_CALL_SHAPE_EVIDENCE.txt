Addendum — boolean membership predicate is not an assertion (Finding 3)
===========================================================================

Reviewed head: d9e0d2153a7b5701055cd00949a06ec66f11494f
Scope: scripts/ci/check_definer_guards.py + scripts/ci/test_check_definer_guards.py
Migration 191 production SQL remains byte-unchanged (sha256 637a81ca…).

Defect
------
wardah_is_org_member(uuid) returns BOOLEAN and does not raise on denial, so a
call whose result is discarded authorizes nothing. The generic call-shape
matcher accepted it anyway.

RED reproduction at d9e0d21, through the real check_file(), each with a
privileged write (UPDATE public.bins) after the call:

  PERFORM public.wardah_is_org_member(p_org);      -> check_file() == []  FALSE GREEN
  SELECT  public.wardah_is_org_member(p_org);      -> check_file() == []  FALSE GREEN
  PERFORM wardah_is_org_member(p_org);             -> check_file() == []  FALSE GREEN
  SELECT  wardah_is_org_member(p_org) INTO v_ok;   -> check_file() == []  FALSE GREEN

Impact survey BEFORE changing anything
--------------------------------------
Removing the predicate from the generic list alone would newly fail 19
SECURITY DEFINER functions across five migrations: 153 (1), 166 (2), 167 (1),
168 (5), 169 (10). Each was inspected. Every one is genuinely guarded by the
negated raising idiom, e.g.

  IF v_org IS NULL OR NOT public.wardah_is_org_member(v_org) THEN
    RAISE EXCEPTION 'TENANT_MEMBERSHIP_REQUIRED';
  END IF;

A repository-wide search found NO discarded-boolean call in any migration or
baseline file: the only non-negated occurrences are to_regprocedure(
'public.wardah_is_org_member(uuid)') preflight existence checks in 167 and 168,
which live inside single-quoted literals and are masked before scanning. So the
false green was real in the scanner but unexploited in the repository, and there
is no production security defect.

Correction
----------
1. wardah_is_org_member is REMOVED from GUARD_NAMES. The generic list now holds
   only the three helpers that raise on denial:
     wardah_assert_org_member, wardah_assert_org_admin,
     wardah_178_assert_permission
2. It moves to BOOLEAN_PREDICATES and is recognized ONLY in the negated raising
   idiom, verified STRUCTURALLY rather than by a flat regex:
     - _if_blocks_with_raising_deny_branch() walks IF / THEN / ELSIF / ELSE /
       END IF as balanced tokens (END IF consumed before a bare IF; ELSIF is one
       word so it cannot open a block) and returns the condition span of each IF
       whose OWN deny branch raises at its OWN nesting level.
     - The negated call must lie inside one of those condition spans.
     - RAISE NOTICE/WARNING/INFO/LOG/DEBUG do not count as denial.
     - An unbalanced IF yields no recognized block, so it fails closed.
3. ZERO entries were added to KNOWN_EXEMPT. The 19 functions pass on their own
   real structure, not on an exemption.

Mutants — a nearby RAISE is not enough (all REJECTED after the correction)
-------------------------------------------------------------------------
  predicate_not_negated          IF pred(...) THEN RAISE      (raises for MEMBERS)
  raise_only_in_else_branch      deny path does nothing
  raise_only_in_nested_if        raise conditional on something else
  raise_is_only_a_notice         RAISE NOTICE does not abort
  raise_after_end_if             raise outside the deny branch
  predicate_in_body_not_condition  predicate not in the IF condition

Accepted — the real idiom (all ACCEPTED after the correction)
-------------------------------------------------------------
  canonical 169 multi-line condition, canonical 153 single-line condition,
  unqualified negated call, bare RAISE with no level.

Addendum 2 — the deny branch must actually be reachable (Finding 4)
===========================================================================

Reviewed head: 44518a9645b9a290ec62314e5e22555d2cc3ff29
Scope: scripts/ci/check_definer_guards.py + scripts/ci/test_check_definer_guards.py
Migration 191 production SQL remains byte-unchanged (sha256 637a81ca…).

Two defects, both reproduced live through the real check_file() at 44518a9,
each with a privileged write after the block:

  A. Conjunction suppresses the deny branch
       IF NOT public.wardah_is_org_member(p_org) AND false THEN
         RAISE EXCEPTION 'DENIED';
       END IF;
     -> check_file() == []   FALSE GREEN
     Also false green: `false AND NOT pred(...)`, `NOT pred(...) AND v_flag`,
     and the same buried inside parentheses.

  B. A quoted identifier satisfied the structural RAISE detector
       IF NOT public.wardah_is_org_member(p_org) THEN
         PERFORM 1 AS "RAISE";
       END IF;
     -> check_file() == []   FALSE GREEN
     The masker blanked comments, string literals and dollar-quoted content but
     kept "quoted identifiers", so non-executable text was read as PL/pgSQL.

Correction
----------
A. The negated predicate must be an ENTIRE top-level condition term: the whole
   condition, or one complete top-level OR disjunct. Rationale: in a disjunction
   each disjunct alone suffices to enter the branch, so non-membership by itself
   guarantees the raise; under AND it does not. Implemented as
   _split_top_level_or() (splitting on OR at parenthesis depth 0) plus
   _is_sole_negated_predicate(), which strips balanced outer parentheses,
   requires the term to begin with NOT [public.]predicate( and consumes the
   call's balanced argument list, rejecting the term if anything follows.

B. _mask_quoted_identifier() blanks the CONTENT of "quoted identifiers" while
   keeping both delimiters, honouring the doubled "" escape and raising
   MaskError (fail closed) on an unterminated one. Offsets and newlines are
   preserved, so the existing offset contract still holds.

Mutants — all REJECTED after the correction
-------------------------------------------
  negated_predicate_and_false, false_and_negated_predicate,
  negated_predicate_and_other_condition,
  negated_predicate_inside_parenthesised_and,
  quoted_identifier_named_raise, quoted_identifier_raise_exception

Accepted — safe boolean forms
-----------------------------
  NOT pred(...) as the whole condition
  v_org IS NULL OR NOT pred(v_org)        (canonical 153)
  NOT pred(v_org) OR v_org IS NULL        (disjunct first)
  v_org IS NULL OR (NOT pred(v_org))      (parenthesised disjunct)
  the canonical 169 multi-line condition with a nested call in the argument

Correction
----------
A. Swallowing — applies to ALL migrations, no cutoff.
   parse_blocks() models BEGIN / IF / LOOP / CASE nesting and EXCEPTION
   sections. is_swallowed() rejects a guard only when a block that ACTUALLY
   ENCLOSES it has handlers able to catch a PL/pgSQL P0001 assertion:
   WHEN OTHERS, WHEN raise_exception, WHEN SQLSTATE 'P0001'. An unrelated
   condition (unique_violation) does not count, and a later non-enclosing nested
   handler does not invalidate a guard. The same test is applied to the boolean
   guard's own RAISE. Impact on existing migrations: 0.

B. Reachability — a forward syntactic contract, MIGRATION_STRICT_CUTOFF = 191.
   For migrations >= 191 a guard counts only at the function's OUTER PL/pgSQL
   statement level: not under IF/ELSIF/ELSE, LOOP/WHILE/FOR/FOREACH, CASE, a
   nested BEGIN, or an EXCEPTION handler. The guard need NOT be the literal
   first statement — identity/org-resolution reads before it are legitimate and
   are covered by a positive control. Migrations <= 190 are immutable historical
   inputs and keep their validated compatibility. The cutoff is a migration
   NUMBER, so the four historical trigger/conditional functions above need no
   exemption and no edit. No general control-flow analysis is attempted.

---------------------------------------
  migration_number = 191  ->  strict = True
  check_file(191)  ->  0 errors
  ==> Migration 191 passes the strict contract UNCHANGED. The rule therefore
      begins AT 191, as required, and no weakening was needed.

  6 guard swallowed by WHEN raise_exception   rejected
  7 guard swallowed by WHEN SQLSTATE 'P0001'  rejected
  8 boolean guard nested under IF false       rejected

Discrimination — MUST ACCEPT (synthetic 999_, strict)
-----------------------------------------------------
  outer-level wardah_assert_org_member / _org_admin / wardah_178_assert_permission
  outer-level canonical negated wardah_is_org_member + RAISE
  org resolution before the assert (M191's real shape)
  unrelated unique_violation handler          accepted (no false red)
  later NON-ENCLOSING WHEN OTHERS block       accepted (no false red)

Scope principle
---------------
This scanner is a syntactic security gate, not a PL/pgSQL theorem prover. From
191 on, new SECURITY DEFINER code must use an authorization shape the scanner
can prove: a simple assertion at the outer statement level. Code needing a
complex conditional authorization architecture should be refactored to an
explicit top-level assertion boundary rather than weakening this gate.

Addendum 4 — a guard past a terminating RETURN is dead (Finding 6)
===========================================================================

Reviewed head: 5d7c16c8378c5adad67eb3fae26e064a0fad13a6
Scope: scripts/ci/check_definer_guards.py + scripts/ci/test_check_definer_guards.py
Migration 191 production SQL remains byte-unchanged (sha256 637a81ca…).

Defect
------
The strict contract modelled BEGIN/IF/LOOP/CASE nesting but not function exit.
_BLOCK_TOKEN_RE never contained RETURN, so an outer-level, non-swallowed
assertion counted even when the invocation could already have ended.

RED reproduction at 5d7c16c, through the real check_file(), strict (999_):

  UPDATE public.bins SET actual_qty = 0 WHERE org_id = p_org;
  RETURN;
  PERFORM public.wardah_assert_org_member(p_org);
    -> check_file() == []   FALSE GREEN   (guard is unconditional dead code)

  IF p_skip THEN RETURN; END IF;
  PERFORM public.wardah_assert_org_member(p_org);
    -> check_file() == []   FALSE GREEN   (guard skipped for p_skip = true)

  RETURN 1; PERFORM public.wardah_assert_org_member(p_org);   -> []  FALSE GREEN
  RETURN; IF NOT public.wardah_is_org_member(v_org) THEN RAISE ...  -> []  FALSE GREEN

Correction (migrations >= MIGRATION_STRICT_CUTOFF only)
-------------------------------------------------------
terminating_return_before(body, pos): a candidate guard does not satisfy the
strict gate when any terminating RETURN precedes it textually. Applied to both
the raising assertion helpers and the structural boolean guard.

  - A plain RETURN, with or without an expression, ends the invocation.
  - RETURN NEXT and RETURN QUERY do NOT terminate a set-returning function and
    are explicitly not treated as exits.
  - `RETURNS` in the function header is not a word match for RETURN.

The rule is deliberately conservative and purely textual: it makes no attempt to
prove that every return path is guarded. It may reject a complex future function
whose returns are all provably guarded; the remedy there is to move the
authorization boundary earlier, never to weaken the gate.

Migration 191 form inventory: 28 RETURN statements, all plain RETURN — no
RETURN NEXT and no RETURN QUERY — so the accurate treatment above carries no
risk for this migration.

MIGRATION 191 UNDER THE NEW RULE
--------------------------------
  check_file(191) -> 0 errors
  ==> Migration 191 PASSES UNCHANGED. Every scanned M191 SECURITY DEFINER
      function places its authorization boundary before any terminating RETURN.

Discrimination — MUST REJECT (strict)
-------------------------------------
  bare RETURN before the assertion
  RETURN <expression> before the assertion
  conditional early RETURN before the assertion
  boolean negated-raise guard after a bare RETURN
  boolean negated-raise guard after a conditional early RETURN

Discrimination — MUST ACCEPT (strict)
-------------------------------------
  assertion then bare RETURN
  assertion then RETURN <expression>
  boolean guard then RETURN
  M191's shape: resolve org -> assert -> privileged work -> RETURN

Historical compatibility
------------------------
  150_… with RETURN before the guard: ACCEPTED (placement rules are cutoff-scoped)
  191_… with the same shape:          REJECTED
