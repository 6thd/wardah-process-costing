Defect
------
At c926e22185e4c0b6dd34aa92a8a614faff3940af the masker was correct, but the
verdict came from `GUARD_RE.search(body)` with GUARD_RE matching the guard NAME
alone. Masking deliberately preserves delimiters and identifiers, so any
non-executable appearance the masker keeps still satisfied the security gate.

RED reproduction against the OLD implementation, through the real check_file()
-----------------------------------------------------------------------------
All seven probes below returned check_file() == []  (FALSE GREEN) for a

  admin_outer_delimiter_is_guard_name        -> []   AS $wardah_assert_org_admin$

None of these shapes was already rejected: every one of the additional probes
(quoted alias, bare non-call identifier) was a live false green, not a
pre-existing rejection.

Matcher change
--------------
Before:
  GUARD_RE = re.compile("|".join(GUARD_PATTERNS))          # bare name

After:
  GUARD_CALL_PATTERN = (
      r"(?<![\w$\".])(?:public\s*\.\s*)?(?:" + "|".join(GUARD_NAMES) + r")\s*\("
  )
  GUARD_RE = re.compile(GUARD_CALL_PATTERN, re.IGNORECASE)

A recognized guard must now have an executable FUNCTION-CALL SHAPE: the name,
optional whitespace, `(`. The optional `public.` qualification is retained. The
left boundary rejects an identifier character, a dollar-quote tag `$`, a quoted
identifier `"`, and a foreign schema qualifier `.`. Masking of comments,
string literals, nested block comments and nested dollar-quoted CONTENT is
retained unchanged; fail-closed behaviour on unmaskable constructs is retained
unchanged.
