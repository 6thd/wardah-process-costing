## 2) ما تبنيه 206

- **8 مفاتيح عادية** في وحدة التصنيع: `bom_snapshots.{create,change,approve}`،
  `production_records.{record,approve,approve_late}`، `production_inputs.{record,approve}`. ليست حساسة، وتمر عبر
  `has_permission` (فيبقى تجاوز مسؤول المؤسسة للمفاتيح، **لكن لا يتجاوز فصل المسؤوليات**: لا يعتمد أحد ما سجّله بنفسه).
- **جداول خاصة** في `wardah_internal` بلا أي امتياز للعملاء: التقويم، إعدادات التسجيل وسجل تدقيقها، اللقطات وسطورها
  وعملياتها، سجلات الإنتاج، المدخلات. التاريخ لا يُعدَّل ولا يُحذف (Trigger)؛ الانتقالات المسموحة فقط:
  مسودة → مقدَّم → معتمد/مرفوض، ومسودة/مقدَّم → مسحوب. حذف أمر تصنيع له سجلات يُرفض (`RESTRICT`).
- **9 دوال RPC** لـ`authenticated` فقط، كل منها `SECURITY DEFINER` تبدأ بـ`wardah_assert_org_member` ثم فحص المفتاح:
  `rpc_add_mfg_period_calendar_206`، `rpc_set_mfg_late_entry_window_206`، `rpc_create_mo_bom_snapshot_206`،
  `rpc_approve_mo_bom_snapshot_206`، `rpc_withdraw_mo_bom_snapshot_206`، `rpc_record_production_206`،
  `rpc_record_production_input_206`، `rpc_transition_production_entry_206`، `rpc_get_mo_production_206`.
- **لا أثر مخزني ولا WIP ولا تكلفة مرحلة ولا GL.** هذه للمراحل 207–209.

### التواريخ الأربعة (R4)

| الحقل | المصدر |
|---|---|
| `entered_at` | الخادم (`now()`) |
| `executed_from` / `executed_to` | المسجِّل؛ فترة نصف مفتوحة `[from, to)`؛ لا مستقبل؛ لا قبل أول إصدار تقويم |
| `execution_period_start` | شهر التاريخ المحلي لـ`executed_from` في إصدار التقويم الساري |
| تاريخ الترحيل | **ليس في 206** (207، مع P-CLOSED-PERIOD) |

### نسب السجل إلى اللقطة (ب4)

اللقطة = آخر لقطة معتمدة وقت سريانها ≤ `executed_from`. سجل يعبر وقت سريان لقطة لاحقة يُرفض
(`MFG_PRODUCTION_SPANS_SNAPSHOT_CHANGE`) ويُقسَّم. واعتماد لقطة بديلة يُرفض ما دام أي سجل أو مدخل حي ينتهي بعد وقت
سريانها (`MFG_BOM_SNAPSHOT_CHANGE_CONFLICTS_RECORDS`)، فلا تتغير لقطة كمية مسجلة بأثر رجعي أبدًا. قفل استشاري لكل أمر
يسلسل المسارين (مثبت بجلستين بالترتيبين)، ولا يقفل صف الأمر، فلا يتداخل مع ترتيب قفل MO→WO في M192/M195.

### الكمية المتوقعة في اللقطة

`qty_per_unit = quantity_base ÷ كمية رأس BOM × (1 + scrap_factor/100)` بدقة كاملة؛ `yield_percentage` لا يدخل (ب1)؛
سطر `REFERENCE` = صفر. مثال القبول: BOM-3 (0.05، 2%) = 0.051، وBOM-4 (0.06، 2%) = 0.0612.

## 5) قبل أي تطبيق (عند التفويض)

1. سجل Production الحي يحتوي 205 مرة واحدة مع postflight ناجح. **206 لا تُطبَّق قبل 205.**
2. الملف من `main` بالضبط (بعد الدمج)، والاسم المرسل = `206_production_recording_foundation`.
3. فحص ب2 على البيانات المخزنة (قراءة فقط) — للعلم، فالقيد قائم:

```sql
SELECT org_id, count(*) AS lines,
       count(*) FILTER (WHERE scrap_factor > 0 AND scrap_factor < 1) AS fractional_looking,
       max(scrap_factor) AS max_scrap
FROM public.bom_lines GROUP BY org_id ORDER BY org_id;
```

   القيم بين 0 و1 داخل المدى في التفسيرين، لكنها قد تكون كسورًا أُدخلت بنية «2%». لا تُعدَّل آليًا؛ تُراجع مع المصنع.
4. تطبيق في معاملة واحدة يملكها المشغّل (`psql --single-transaction`)؛ الملف بلا BEGIN/COMMIT.

WHERE permission_key LIKE 'manufacturing.bom_snapshots.%'
   OR permission_key LIKE 'manufacturing.production_records.%'

SELECT count(*) FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace
WHERE n.nspname = 'public' AND p.proname LIKE 'rpc\_%\_206' ESCAPE '\';   -- 9
SELECT count(*) FROM wardah_internal.mfg_period_calendars_206;           -- 0 (لا بذرة)
SELECT count(*) FROM wardah_internal.mfg_recording_settings_206;         -- 0 (لا مهلة مفترضة)
